# 1. 概要

## 1.1 本書の目的

本書は、国内船主（特に一杯船主等の中小事業者）が内航船運航において日常的に行っている業務を体系的に整理・定義し、船員業務管理アプリケーションの開発における機能設計の基礎資料とするものである。

内航海運業界は、国内貨物輸送の約4割（輸送活動量ベース）を担う重要な産業でありながら、慢性的な船員不足（50歳以上が約半数）、老朽船の増加、紙・FAX・Excel中心のアナログ運用といった構造的課題を抱えている。本業務定義書は、これらの課題をDXにより解決するための第一歩として位置づけられる。

## 1.2 対象ユーザー

- 一杯船主（保有船舶1〜2隻の個人事業主）

- 中小規模船主（保有船舶数隻〜10隻程度）

- 船舶管理会社（テクニカルマネジメント受託者。改正内航海運業法に基づく登録船舶管理事業者を含む）

- 船内利用者（船長・航海士・機関士・部員）

- 陸上の労務管理責任者（船員法第67条の2に基づく選任者）

## 1.3 業界構造の前提

内航海運の運航形態は、以下のプレーヤーが関わる多層構造となっている。改正内航海運業法（令和4年4月施行）により、オペレーターには船員の労働時間を考慮した運航計画の作成と船舶所有者からの意見の尊重が義務付けられ、荷主に対する勧告・公表制度も設けられた。アプリはこの「荷主・オペレーター・オーナー間の説明責任」を支えるデータ基盤としての役割も担う。

| **プレーヤー**   | **役割**                                                                                                                     | **アプリとの関係**                             |
|------------------|------------------------------------------------------------------------------------------------------------------------------|------------------------------------------------|
| 荷主             | 貨物の委託元。運賃支払い。<br>船員の労働時間に配慮する対象。改正内航海運業法に基づく勧告・公表制度の対象。                   | 報告データの受け取り先・労働時間配慮の確認者   |
| オペレーター     | 配船・運航指示を行う内航運送事業者。<br>船員の労働時間を考慮した運航計画の作成義務、オーナーからの意見陳述の尊重義務を負う。 | 運航実績・労務データの共有先。意見陳述の相手方 |
| オーナー（船主） | 船舶保有・船員配乗・安全管理の主体。労務管理責任者の選任義務者                                                               | アプリの主たる利用者（管理者側）               |
| 船員             | 船内での運航・機関運転・荷役作業を実施                                                                                       | アプリの主たる利用者（船内側）                 |
| 船舶管理会社     | 船主に代わり船員配乗・保守管理を受託。<br>改正内航海運業法により船舶管理業の登録制度が導入。                                 | アプリの利用者（管理代行者側）                 |

# 3. 業務定義詳細

## 3.1 船員配乗・人事管理

船員の採用から配乗、資格管理、健康管理まで、「人」に関する一連の業務を包括する。小規模事業者では社長自らが手作業で管理するケースが一般的である。

### 3.1.1 船員マスターデータ管理

|                    |                                                                                                                                                                                                                                                                                                                                           |
|--------------------|-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **業務名**         | 船員マスターデータの登録・更新・照会                                                                                                                                                                                                                                                                                                      |
| **業務説明**       | 船員一人ひとりの基本情報、海技免状情報、健康診断書情報、乗船履歴、緊急連絡先等を一元管理する。                                                                                                                                                                                                                                            |
| **管理データ項目** | 氏名 / 生年月日 / 船員手帳番号 / 雇入契約情報 / 顔写真 / 住所 / 血液型 / 海技免状（種類・等級・有効期限）/ 健康診断書（有効期限・結果）/ 安全訓練受講履歴 / 緊急連絡先 / 業務態度評価履歴 / 人事考課記録 / STCW基本訓練修了証・実技講習修了証（種類・修了日・有効性）/ 船員保険・労災保険・雇用保険の加入確認情報（記号番号・資格取得日） |

| **DX化のポイント** | 免状・健康診断・基本訓練修了証の期限自動アラート、一元検索、資格マッチング。雇入届出書類への自動引用による入力レス化。カメラや電子データによる自動入力。                                                                                                                                                                                  |

### 3.1.2 配乗計画・乗下船管理

|                      |                                                                                                                                                                                                    |
|----------------------|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **業務名**           | 船員の配乗・乗下船スケジュール管理                                                                                                                                                                 |
| **業務説明**         | 各船舶への船員配置を計画し、乗船・下船日程を調整する。法定定員を満たす資格保有者の配置、乗船期間のバランス、休暇ローテーションを考慮した組み替え計画を作成する。                                   |
| **関連法令**         | 船舶職員及び小型船舶操縦者法（定員規定）/ 船員法（雇入契約の届出、乗下船手続） / 船員法第81条の2等（基本訓練。雇入時に修了確認が必要）                                                             |
| **サブプロセス**     | ① 各船の必要定員・資格要件の確認 ② 配乗待ち船員の資格・訓練修了・保険加入状況の確認 ③ 乗船日程の調整・通知 ④ 乗船・下船実績の記録 ⑤ 雇入契約届出の準備（基本訓練修了証・保険加入確認を含む）       |

### 3.1.3 海技免状・資格・訓練管理

船員が保有する海技免状の種類、等級、有効期限、更新講習受講状況を管理する。

- 海技免状の種類：航海（1級〜6級）、機関（1級〜6級）、通信、電子通信

- 小型船舶操縦士免許：1級・2級・特殊

- 無線従事者資格：第二級海上特殊無線技士以上

- 海技免状更新講習の受講管理（5年ごとの更新）

- STCW基本訓練修了証・実技講習修了証の管理 ：2026年2月14日以降、雇入契約成立の届出時に修了証の提示が求められ、確認できない場合は届出の受理が保留されうる。有効性・修了日・登録実技講習機関名を管理する。

- 資格認定方法の拡大対応 ：航海当直部員・危険物等取扱責任者・特定海域運航責任者の認定方法拡大（2026年4月1日施行）に伴う認定情報の管理。

### 3.1.4 船員情報管理（写真付きプロフィール）

※ 本プロフィールは 3.1.1 船員マスターデータの参照ビューとして実装し、独立したデータ保持は行わない。項目の正本・更新経路・導出値の扱いは 12 章「データ整合性・正本管理」に定める。

### 3.1.5 業務態度評価・人事考課

|                  |                                                                                                                                                              |
|------------------|--------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **業務名**       | 船員の業務態度評価・人事考課記録                                                                                                                             |

## 3.2 労務管理・働き方改革対応

令和3年成立の海事産業強化法による改正船員法（**令和4年（2022年）4月施行**）により、船舶所有者には労務管理責任者の選任、労務管理記録簿（第16号の5書式）の作成・備置き、および客観的な方法による労働時間の状況把握が義務付けられた（船員法第67条・第67条の2）。さらに**令和5年（2023年）4月施行の労働時間範囲の見直し**により、荷役待ち等の総員配置（スタンバイ）での待機時間は労働時間に算入される等、労働時間の範囲が明確化された。国交省「船員の労務管理の適正化に関するガイドライン」に沿った作業種別の設計（航海当直/荷役/スタンバイ/保守整備/その他作業 等）を打刻の前提とする。

### 3.2.1 労働時間・休息時間記録（打刻）

- 船員自身による日次の打刻（作業種別選択→開始/終了打刻）。

> モバイル・タブレット・船内共用端末に対応

- 後から打刻（事後入力・修正依頼対応）と、日付入力誤り・打刻誤りを防止するUI

- 打刻認証は運用に応じ選択可能（認証なし＋打刻者表示 / IC カード / 生体 / パスワード）

- 自動集計機能（日単位・週単位・4週単位・月単位）

- 休息時間の自動計算・分割回数チェックと遵守状況確認

- 船員の実打刻時間は事後改変不可（承認者も修正不可、修正は本人への差戻しのみ）とし、変更履歴を保全する

- オフライン時は端末内に蓄積し、オンライン復帰時に自動同期

### 3.2.2 労務管理記録簿の作成・出力

- 第16号の5書式に準拠した労務管理記録簿の自動生成

- 電子保管とPDF出力機能（英語版様式にも対応可能な設計とする）

- 労働時間・休日・有給休暇の一覧表示

- 海上労働検査・行政監査時の提出資料としての出力

- 国交省公表の労務管理記録簿Excelマクロデータのインポート ：既にExcelマクロで運用中の事業者からの移行を容易にする

### 3.2.3 当直・シフト管理

航海当直（0-4/4-8/8-12直等）、停泊当直、荷役当直などのシフト表を作成・共有し、変更があった場合の通知機能を提供する。不規則勤務の中でも公平な配分と法令遵守を両立させる。通常配置表・運航スケジュールの管理機能を導入。

### 3.2.4 休日・有給休暇・補償休日管理

船員法に基づく休日、補償休日、有給休暇の付与状況を記録・管理し、未消化の休日を可視化する。休暇日数の付与や編集は管理者権限のみが行える。基準労働期間（航行区域等により1月〜1年）に応じた週平均40時間の算定に対応する。

### 3.2.5 法令遵守チェック・アラート

|                  |                                                                                                                                                                                                                |
|------------------|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **チェック項目** | ① 1日の労働時間上限（14時間）② あらゆる連続1週間の上限（72時間）③ 4週間・基準労働期間の時間外上限 ④ 休息時間の回数・長さ・分割 ⑤ 休日付与（週1日以上）⑥ 安全臨時労働・緊急作業の別枠管理（上限算定からの除外） |

## 3.8 一括届出・行政手続自動化

船員が船に乗務する際は、陸上での雇用契約とは別に船舶単位の「雇入契約」が成立し、船長（船長ができない場合は船舶所有者）は成立・終了・更新・変更を**遅滞なく国土交通大臣に届け出る義務**を負う（船員法第37条）。 現行法上この手続は「公認申請」ではなく「届出」であり、本書では用語を「雇入契約成立等の届出（雇入・雇止届出）」に統一する（実務通称としての「公認」は用語集に残置）。

### 3.8.1 背景・法的要件

- 陸上での通常雇用契約（労働契約法に基づく雇用）と、船舶乗務時の雇入契約（船員法第37条に基づく届出義務）の二重構造

- 届出時の必要書類：雇入（雇止）届出書（第六号書式）/ 海員名簿 / 船員手帳 / 資格証明書（海技免状等）/ クルーリスト（海員名簿第六表）2通 / 保険加入確認書類 等

- 保険加入確認：船員保険・労災保険・雇用保険の加入が確認できない場合、届出の受理が保留されうる（平成22年6月〜）

- 基本訓練修了確認：2026年2月14日以降、雇入契約成立の届出時にSTCW基本訓練修了証（特定の船員は実技講習修了証を含む）の提示が必要。未確認の場合は受理保留のリスク。

### 3.8.2 現状の業務フローと課題

| **工程**       | **現状の作業内容**                                                                            | **課題**                                                                            |
|----------------|-----------------------------------------------------------------------------------------------|-------------------------------------------------------------------------------------|
| ① 届出書作成   | 雇入・雇止届出書（第六号書式）をExcelで作成。船員情報を全項目手入力。                         | 同じ船員情報を複数回入力。入力ミスのリスク。                                        |
| ② 添付書類準備 | 海員名簿、船員手帳、資格証明書、クルーリスト2通、保険加入証明、基本訓練修了証等を個別に準備。 | 書類が散在。コピー・整理に時間がかかる。2026年2月以降は修了証不備の受理保留リスク。 |
| ③ 運輸局届出   | 運輸局または指定市町村窓口で届出。                                                            | 移動時間・交通費負担。窓口の営業時間制約。                                          |
| ④ 船員手帳記帳 | 届出後、船員手帳に乗船履歴を記帳。                                                            | 記帳漏れ、手帳紛失時の履歴喪失リスク。                                              |
| ⑤ 複数隻対応   | 保有船舶ごとに上記①〜④を繰り返し実施。                                                        | 船舶数に比例して作業量が膨大化。                                                    |

### 3.8.5 対象業務の範囲

- 雇入届出：新規乗船時の契約成立届出

- 雇止届出：下船時の契約終了届出

- 雇入契約更新：同一内容での期間延長

- 雇入契約変更：職務・労働条件等の変更時の届出

船員手帳の新規交付・書換え・再交付等は対象外（従来どおり窓口での個別申請）。ただし令和7年改正船員法（2026年5月13日施行）により、船員手帳への船長記載・大臣証印は電子書面・電子証書の交付で代替可能となるため、本アプリの乗下船電子記録を電子証明運用へ接続する拡張を第2フェーズ以降で計画する。

## 3.9 訓練・教育管理（STCW基本訓練対応）

令和7年改正船員法（船員法第81条の2等、**2026年2月14日施行**）により、船舶所有者は雇入契約を結んだ際、遅滞なく基本訓練を実施（または修了を確認）させる義務を負い、特定の船員には登録実技講習機関での生存・消火に係る実技講習の受講が義務付けられた。従来「慣習」だった船内教育が法定手続となり、雇入届出時にも修了が確認される。

|              |                                                                                                                                                                                        |
|--------------|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **管理対象** | 基本訓練修了証 / 実技講習修了証（登録実技講習機関名・修了日）/ 船内操練（防火・退船・救命等）の実施記録 / 訓練計画                                                                     |
| **主要機能** | ① 船員ごとの修了状況一覧と未修了アラート ② 雇入届出書類への修了情報自動連携（3.8の添付要件チェッカーと連動）③ 船内操練の実施記録（3.3.2と連携）と次回期日管理 ④ 訓練教材・手順書の配信 |

# 4. 主要業務フロー

## 4.1 配乗計画フロー

① 船舶の運航スケジュールを確認 → ② 必要定員・資格要件をシステムで自動算出 → ③ 配乗可能な船員を資格・訓練修了・保険加入・休暇状況から検索（配乗ブロック条件の自動チェック）→ ④ 配乗計画を作成し、船員へ通知 → ⑤ 乗船・下船実績を記録、雇入契約届出の準備

## 4.2 労働時間管理フロー

① 船員が船内アプリで作業種別を選択して打刻（オフライン時は端末に蓄積）→ ② システムが自動集計（1日14時間・週72時間・4週上限・休息時間のチェック）→ ③ 上限接近で注意（黄）、超過で警告（赤）を船長・陸上労務管理責任者へ通知 → ④ 船内管理者が日次承認、労務管理責任者が確認・承認 → ⑤ 労務管理記録簿（第16号の5書式）を自動生成・保管 → ⑥ 必要に応じオペレーターへ運航計画変更の意見陳述（実績データ添付）

## 4.3 一括届出業務フロー

① 配乗計画確定 → ② 一括登録画面で対象船員・船舶を選択 → ③ 添付要件チェッカーが保険加入・基本訓練修了・免状有効性を自動検証 → ④ 雇入・雇止ステータスを一括更新 → ⑤ 届出書・クルーリストを自動生成 → ⑥（紙運用）PDF一式を窓口へ提出 /（電子運用）登録届出により電子届出 → ⑦ 届出後、船員手帳記帳情報をシステムに反映（将来は電子証明運用へ）

## 4.4 訓練管理フロー

① 新規雇入予定者の基本訓練修了状況を確認 → ② 未修了者に受講手配（登録実技講習機関）→ ③ 修了証をアプリに登録 → ④ 雇入届出書類に自動連携 → ⑤ 乗船後の船内操練を記録し、次回期日を自動管理

# 6. 行政手続き詳細と効率化方針

内航船主（船舶所有者）は、船員法・船舶職員法・内航海運業法・船舶安全法・海上運送法・電波法・社会保険各法という複数の法体系にまたがる行政手続きを、少人数（多くは社長1人）でこなしている。本章では、それらの手続きを「いつ・誰が・どこに・何を」の粒度で棚卸しし、各手続きについて本アプリでどこまで効率化できるか（自動化レベル）を定義する。

## 6.1 自動化レベルの定義と手続き4群マップ

| **レベル** | **意味**                                       | **例**                             |
|------------|------------------------------------------------|------------------------------------|
| **◎**      | 書類自動生成＋電子提出まで                     | 雇入・雇止の登録届出（電子届出）   |
| **○**      | 書類・添付一式の自動生成（提出は紙/持参/郵送） | 雇入届出書・クルーリストのPDF出力  |
| **△**      | 期限管理・アラート・データ準備の支援           | 海技免状更新、船舶検査、健康証明書 |
| **×**      | アプリの対象外（本人出頭・現物確認が必須等）   | 船員手帳の新規交付、海技試験       |

手続きは発生パターンで4群に大別できる。頻度×件数で見ると、負担の中心は「B群：乗下船の都度発生する手続き」と「C群：期限が個人・船舶ごとにバラバラに来る周期手続き」であり、ここが本アプリの主戦場となる。

| C群 周期・期限 | 個人・船舶ごとに期限が分散。失念＝乗船不可・航行不可に直結 | 健康証明書(1年)、海技免状(5年)、船舶検査(5〜6年+中間)、無線局再免許(5年)、STCW基本訓練 |

## 6.3 雇入・雇止届出の「3つの提出方式」とアプリ戦略

雇入・雇止届出には実務上3つの方式があり、どの方式を使えるかで効率化の上限が決まる。本アプリは3方式すべてに対応し、事業者を段階的に電子方式へ引き上げる。

| **方式**                           | **概要**                                                                                                                     | **負担・制約**                                                                                                  | **アプリの役割**                                                                              |
|------------------------------------|------------------------------------------------------------------------------------------------------------------------------|-----------------------------------------------------------------------------------------------------------------|-----------------------------------------------------------------------------------------------|
| **① 都度・窓口届出（デフォルト）** | 乗下船の都度、船長（できない場合は船舶所有者）が運輸局等の窓口で届出。海事代理士への委任も可                                 | 窓口営業時間の制約・移動負担。書類はすべて紙。添付不備（保険・基本訓練・免状）があると受理保留                  | 書類一式の自動生成＋添付要件チェッカーで「一発受理」を保証。海事代理士への依頼パッケージ出力  |
| **② 一括届出（許可制）**           | 適切な労務管理体制を持つ船舶所有者が地方運輸局長の許可を受け、指定事務所でまとめて届出できる制度                             | 一括届出許可申請書の作成・許可維持が必要。乗船履歴の証明は一括届出用の乗船履歴証明書で行う                      | 許可申請書の作成支援。一括処理画面で複数船・複数船員をまとめて処理                            |
| **③ 登録届出（電子届出）**         | 平成15年の省令改正で導入。国交省オンラインシステムに船員等の情報を登録し、電子情報処理組織で雇入契約成立等を一括届出する方式 | 電子届出登録申請書＋電子届出用雇入(雇止)届出書（Excel様式）での運用。対象は労務管理体制の要件を満たす船舶所有者 | **登録申請の支援＋電子届出用Excel様式をマスタから自動生成。窓口出頭ゼロを実現する本命ルート** |

### 段階引き上げシナリオ

- **STEP1（導入直後）：**方式①のまま、書類生成と添付チェックで窓口滞在時間と差戻しをゼロに近づける

- **STEP2（労務管理データが蓄積）：**アプリの労務管理記録簿・承認フローの運用実績を「適切な労務管理体制」の疎明資料として、一括届出許可／電子届出登録の申請を支援

- **STEP3（許可取得後）：**方式③に移行し、乗下船イベント登録→電子届出用様式の自動生成→提出までをワンフローで完結。船員手帳の乗船履歴も一括届出用の履歴証明書で管理

## 6.6 効率化の3原則

- **① イベント駆動の連鎖生成：**「乗下船」「採用」「決算」という業務イベントを起点に、必要な手続き一式（届出＋保険＋記帳＋チェック）を自動で束ねて生成する。手続き単位ではなくイベント単位で設計する。

- **② 期限は「提出期限」でなく「着手期限」で管理：**免状更新は講習・身体検査の段取りが要るため満了日アラートでは遅い。各手続きの準備リードタイムを持たせた逆算リマインドを標準とする。

- **③ 電子方式への段階引き上げ：**紙の効率化で止まらず、労務管理データの蓄積自体を電子届出（登録届出）許可の疎明材料として活用し、最終的に窓口出頭ゼロへ導く。

注：本章は公開情報に基づく調査であり、法令・運用は管轄運輸局により細部が異なる場合がある。実装前に管轄局・海事代理士・社会保険労務士等への確認を推奨する。

# 11. 非機能要件・システム化方針

## 10.1 オフラインファースト設計

- 船内ネットワークが使えなくても法令遵守に必要な業務（打刻・記録・承認）が完結すること

- オフライン時は端末・船内機器のローカルストレージにデータを蓄積し、オンライン復帰時に自動同期。船内では瞬断が頻発する前提で、同期は再開可能・冪等な設計とする

- 陸—船・船内の接続可否4類型（常時接続可 / 陸船間のみ可 / 出航前後のみ可 / 全て不可）ごとに運用構成を選択できること

- 通信量を抑えた差分同期・データ圧縮。衛星通信（低軌道衛星等）の普及を見据えた帯域適応

- 冪等性は再送への耐性を保証するものであり、船内と陸上で同一レコードが独立に更新された場合の競合解決は別要件として定義する（12.5 参照）。

- 同期状態（未同期件数・最終同期日時・競合件数）を船内・陸上の双方で常時可視化する。

## 10.2 ユーザビリティ

- 船員の約半数が50歳以上であることを踏まえ、大きな文字・少ないタップ数・直感的な画面遷移を原則とする

- 打刻は「作業種別を選んで押すだけ」を基本とし、誤打刻防止（日付誤り防止・確認表示・直前打刻のメッセージ表示）を組み込む

- 多言語UI（外国人船員対応）を拡張可能な設計とする

## 10.3 セキュリティ・個人情報保護

- 健康情報等の要配慮個人情報を扱うため、個人情報保護法に準拠し、ロールベースの閲覧権限（本人/船長/労務管理責任者/管理者）、通信・保管の暗号化、アクセスログを必須とする

- クラウド環境は可能な限り国内データセンターとし、データは国内で管理する（国交省要件定義書 4.7 に整合）

- ウイルス対策・不正アクセス検知・DoS対策が講じられたクラウド環境を選定する

## 10.4 可用性・保守・データ保全

- 業務データの定期バックアップ（世代管理）とリカバリ手順の整備

- 打刻データ等の一次記録は改変不可（イミュータブル）とし、監査証跡を保全する

- アプリ更新は事業者側の作業なしで自動配信されること（SaaS型提供を志向）

- 保守用アプリケーションログの出力・世代管理

## 10.5 段階的実装・代替構成

- 必須（法令直結）機能と任意（効率化）機能を区分し、事業者の習熟度に応じて段階導入できること

- 国交省要件定義書 第5章の代替構成案（打刻のみ＋記録簿ファイル運用、船内管理者機能を陸上側に統合 等）に相当する縮退構成をサポートし、導入費用を抑えられること

- 既存パッケージ流用時は Fit&Gap 分析を実施し、導入先の就業規則・労使協定に応じた設定変更で吸収できる範囲を明確化すること

# 12. データ整合性・正本管理【Ver3.2追加】

本アプリケーションは、同一の情報を複数の機能（船員マスター／写真付きプロフィール／届出書類／船内オフライン端末）で扱う。更新経路が複数存在すると、同じ項目に異なる値が並存し、法令対応の判定を誤らせる。本章では、どのデータをどこが正本とし、重複と乖離をどのように防ぐかを定義する。

## 12.1 課題認識

- 項目の重複そのものよりも、更新経路が複数あることが不整合の原因となる。3.1.1 船員マスターデータと 3.1.4 写真付きプロフィールは項目の大半が重複しており、別々に更新できる設計とした場合、健康診断の有効期限と結果が食い違う等の状態が生じる。

- 保険加入情報・海技免状・健康証明書・訓練修了証は、正本が外部機関（日本年金機構・協会けんぽ・運輸局・指定医・登録実技講習機関）に存在し、アプリが保持するのは写しである。写しが古いまま添付要件チェッカー（3.8.3）が「適合」と判定すると、届出の受理保留＝乗船不可に直結する。

- オフライン運用（11.1）では、船内と陸上で同一レコードが独立に更新されうる。冪等性は同じ更新を再送しても壊れないことの保証であり、どちらの更新を採用するかという競合解決は別の要件である。

## 12.2 正本（Source of Truth）の定義

データ区分ごとに正本の所在を定め、アプリが正本を持つものと写しを持つものを明確に区別する。

| **データ区分**                                 | **正本の所在**                           | **アプリでの扱い**                               | **更新経路**                               |
|------------------------------------------------|------------------------------------------|--------------------------------------------------|--------------------------------------------|
| 船員基本情報（氏名・生年月日・船員手帳番号等） | アプリ内 船員マスター                    | 正本として保持                                   | 管理者による登録・更新（単一経路）         |
| 海技免状・無線従事者資格等                     | 運輸局等（免状現物）                     | 写しを保持。原本確認日を必須項目とする           | 現物確認時に更新。確認日・確認者を記録     |
| 健康証明書・健康診断結果                       | 指定医の証明書                           | 写しを保持。有効期限・結果・確認日をセットで管理 | 証明書受領時に更新                         |
| STCW基本訓練・実技講習修了証                   | 登録実技講習機関                         | 写し（画像・PDF）＋修了日・機関名を保持          | 修了証受領時に更新                         |
| 船員保険・労災保険・雇用保険の加入状況         | 日本年金機構・協会けんぽ・ハローワーク等 | 写しを保持。最終確認日と確認方法を必須項目とする | 資格取得・喪失手続の完了通知受領時に更新   |
| 打刻・労働時間記録                             | アプリ内（船内端末の一次記録）           | 正本。追記のみ（イミュータブル）                 | 本人の打刻のみ。修正は差戻しによる新規記録 |
| 航海日誌・点検記録・作業記録                   | アプリ内（船内の一次記録）               | 正本。追記のみ                                   | 船内での記録。訂正は訂正記録として追記     |
| 就業規則・労使協定                             | 運輸局に届出済みの版                     | 版管理。届出日・適用期間を保持                   | 届出完了時に版を確定                       |

## 12.3 重複保持の禁止（単一実体の原則）

- 3.1.4 写真付きプロフィールは、3.1.1 船員マスターデータの参照ビューとして実装し、独立したデータ保持を行わない。プロフィール固有に見える項目（既往歴・服薬状況・家族構成等）もマスターの属性として保持し、表示可否は閲覧権限で制御する（10.3 と整合）。

- 3.1.4 の「配乗可否ステータス」は入力項目ではなく、免状期限・健康証明書期限・基本訓練修了・保険加入確認・直近の労働／休息時間から算出する導出値とする。判定ロジックは 3.1.2 の配乗ブロック条件と共通のものを用い、二重に実装しない。

- 年齢等の導出可能な値は保持せず、生年月日から算出して表示する。

- 届出書類（第六号書式・クルーリスト等）は、生成時点のマスター値のスナップショットを提出物として保存する。以後マスターが更新されても提出済み書類は書き換えず、提出時点の証跡として保全する。

- 同一項目を複数画面から更新できる導線を設けない。更新は所定の1画面に集約し、他画面からは参照のみとする。

## 12.4 鮮度管理（外部に正本があるデータ）

- 外部に正本があるデータは、有効期限とは別に「最終確認日」および「確認方法（現物確認／通知書受領／外部連携）」を保持する。

- 最終確認日から一定期間（既定：180日。項目ごとに設定可能）確認がないものを「未確認」として検知する。

- 添付要件チェッカー（3.8.3）は、有効期限内であっても最終確認日が閾値を超えるデータについて「要再確認」を警告する。有効期限切れ（不適合）とは区別して表示する。

- 期限アラート（3.1.1）は満了日ではなく「着手期限」（6.6 ②）で発報し、鮮度アラートとは別種のアラートとして区別する。

## 12.5 オフライン同期時の競合解決

競合解決ポリシーは Phase 1（オフライン運用の開始時点）で必要となるため、必須要件として定義する。CRDT 等の実装手段の採否は本ポリシーを満たす方式の選定として扱う。

| **レコード種別**                           | **競合解決規則**                                                             | **根拠**                                               |
|--------------------------------------------|------------------------------------------------------------------------------|--------------------------------------------------------|
| 打刻・一次記録（労働時間・航海日誌・点検） | 追記のみとし、上書きしない。船内・陸上いずれの記録も残す                     | 実打刻は事後改変不可とする要件（3.2.1）                |
| 船員・船舶マスター                         | 陸上を優先。船内での変更は「変更依頼」として起票し、陸上の承認を経て反映する | 届出書類の入力元であり、単一経路で管理する必要がある   |
| 承認ステータス（日次承認等）               | 承認者の役割で優先順位を定義する（労務管理責任者＞船長）                     | 承認権限の階層が法令上定まっている（船員法第67条の2）  |
| シフト・配乗計画                           | 陸上を優先。船内での実績は別レコードとして保持し、計画と実績を分離する       | 計画の変更権限は陸上にあり、実績は船内の一次記録である |
| 上記で自動解決できない場合                 | いずれの値も破棄せず「要確認」として双方を保持し、管理者に提示する           | データの欠落を防ぎ、判断を人間に残す                   |

- 同期状態（未同期件数・最終同期日時・競合件数）を船内・陸上の双方の画面に常時表示し、未同期のまま運用が継続することを防ぐ。

- 競合の発生件数・解決結果を記録し、運用改善の指標とする。

## 12.6 監査証跡

- すべてのマスター更新について、変更前後の値・変更者・変更日時・変更経路（陸上／船内／外部連携）を保持する。

- 要配慮個人情報（既往歴・服薬状況等）は、更新だけでなく参照についてもアクセスログを記録する（10.3 と整合）。

- 外部システム連携により自動更新される項目は、連携元・取得日時を併せて記録し、手動更新と区別できるようにする。
