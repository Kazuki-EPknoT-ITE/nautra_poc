# Nautra（ノートラ）PoC — 船員業務管理アプリケーション

`projects/docs/` の要件定義書（Ver3.2 相当）・基本設計書（Ver1.2）に基づく
Phase 1 コア機能の PoC。Next.js 15 + HeroUI + Tailwind CSS + Dexie(IndexedDB) + Zod。

## 起動

```bash
npm install
npm run dev   # http://localhost:3100
```

初回起動時、陸上ストア（`.data/store.json`）に過去6日分のデモ打刻・承認が
シードされ、船内アプリは初回 Pull で受信します。

## 画面

| パス | 画面 | 設計書ID |
|---|---|---|
| `/` | 入口（船内/陸上の選択） | — |
| `/vessel` | 打刻ホーム（作業種別大ボタン・2タップ打刻） | V-01 |
| `/vessel/history` | 打刻履歴・後から打刻・差戻し再入力 | V-02 |
| `/vessel/today` | 本日の労働・休息（日/週/4週ゲージ・2段階アラート） | V-03 |
| `/vessel/approve` | 船内承認（船長の承認・差戻し） | V-04 |
| `/vessel/sync` | 同期状態（未同期件数・擬似オフライン・手動同期） | V-09 |
| `/shore` | 労務ダッシュボード（アラート集計・承認状況・受信状況） | S-01 簡易版 |

## デモシナリオ（シードデータ）

- 佐藤（航海士）: 3日前に 14.5h 労働 → **警告(赤)**。船長差戻し済み → 履歴画面で再入力を体験可
- 佐藤: 前日 13h 労働 → **注意(黄)**。週合計は 72h 上限の9割超 → 週次注意
- 鈴木（機関長）: 2日前に休息4分割 → **分割回数超過の警告(赤)**
- 田中（甲板部員）: スタンバイ（荷役待ち待機）の労働時間算入例

## 検証ポイント（PoC の目的）

1. **オフラインファースト**: 打刻は常にローカル先行（IndexedDB）→ 送信キュー →
   冪等 Push / カーソル Pull。擬似オフライン→復帰→自動回復を UI で確認できる
2. **法令判定の定義駆動**: 判定閾値は rule_sets 相当から注入。テストが仕様書
   （`src/domain/labor-law/__tests__/`）
3. **一次記録のイミュータブル性**: 訂正は差戻し→ supersedesId 付き再入力。原本保持
4. **HeroUI の2テーマ**: 船内（大文字・高コントラスト・64px ボタン）/ 陸上（情報密度）

詳細な規約・本番との差分は `CLAUDE.md` を参照。
