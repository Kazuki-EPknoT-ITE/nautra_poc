# Nautra（ノートラ）PoC — 船員業務管理アプリケーション

`projects/docs/` の要件定義書（Ver3.2 相当）・基本設計書（Ver1.2）に基づく
Phase 1 船内機能（01〜06）の PoC。Next.js 15 + HeroUI + Tailwind CSS + Dexie(IndexedDB) + Zod。

## 起動

```bash
npm install
npm run dev   # http://localhost:3100
```

初回起動時、陸上ストア（`.data/store.json`）に過去6日分のデモ打刻・承認と船内記録・
当直シフト計画がシードされ、船内アプリは初回 Pull で受信します。
デモデータ版（`src/lib/seed.ts` の `SEED_VERSION`）が上がるとストアは作り直され、
船内端末はストア変更を検知してレプリカを取り直します（未送信の記録は保持）。

## デモシナリオ（シードデータ）

- 佐藤（航海士）: 3日前に 14.5h 労働 → **警告(赤)**。船長差戻し済み → 履歴画面で再入力を体験可
- 佐藤: 前日 13h 労働 → **注意(黄)**。週合計は 72h 上限の9割超 → 週次注意
- 鈴木（機関長）: 2日前に休息4分割 → **分割回数超過の警告(赤)**
- 田中（甲板部員）: スタンバイ（荷役待ち待機）の労働時間算入例
- 航海: 2日前 横浜→名古屋（出港・定時記録・入港）、前日 名古屋で荷役待ち 3h → 揚荷 1,200t、燃料補給
- 点検: 2日前 出港前点検（合格）・アルコール検知（全員適合）、前日 安全パトロール（通路に工具放置 → 不合格・是正済）、5日前 防火操練
- 保守: 前日の日常点検で 発電機=要注意、No.2 ウインチ=不良（部品手配）→ メニュー 05 に「不良 1件」
- シフト: 本日の佐藤 荷役当直 12–18 → 13–19 に陸上が変更 → メニュー 04 のカードに「変更通知 1件」

## 検証ポイント（PoC の目的）

1. **オフラインファースト**: すべての記録は常にローカル先行（IndexedDB）→ 送信キュー →
   冪等 Push / カーソル Pull。擬似オフライン→復帰→自動回復を UI で確認できる
2. **法令判定の定義駆動**: 判定閾値は rule_sets 相当から注入。テストが仕様書
   （`src/domain/labor-law/__tests__/`）
3. **一次記録のイミュータブル性**: 訂正は差戻し→ supersedesId 付き再入力／訂正記録の追記。原本保持
4. **エンティティレジストリ方式の同期**: 記録種別の追加は Zod スキーマ登録のみ
   （`src/sync-protocol/records.ts` / `events.ts`。テスト `__tests__/records.test.ts`）
5. **計画・実績分離**: シフト計画は陸上正本、船内の打刻実績と対比表示（上書きしない）
6. **HeroUI の2テーマ**: 船内（白ベース・大文字・64px ボタン）/ 陸上（白ベース・情報密度）
7. **リキッドガラス・白黒基調**: 材質は globals.css に集約。白ベース＋黒の primary で、
   法令アラートの黄／赤・判定の緑のみ色を保持（アイコン・文言を併記）。カードは
   タイトルと操作ボタンのみで説明文を持たない

詳細な規約・本番との差分は `CLAUDE.md` を参照。
